## Context

目前运行参数都放在 `src/config.py` 的模块级可变变量里（约 50 个）。`main._apply_cli_overrides()`
在启动时直接改写这些全局变量（`config.X = ...`），甚至会原地修改 `config.SKIP_CODECS` 这个 set。
业务模块再各自 `from src import config` 去读。后果有三个：同一进程里，一个测试的 CLI 覆盖会
污染后面的测试；`pipeline.vmaf_mode` 和 `config.VMAF_MODE` 两个来源可能不一致；也没有一个对象能
代表“本次运行实际生效的配置”。

本任务是整个迁移的地基：先把冻结的配置模型和它的构造入口建起来，**运行行为完全不变**。
业务模块这次一个都不改。

## Goal

可以通过纯函数 `config.build_settings(args)` 从“默认值 + `libraries.conf` + CLI 参数”得到冻结的
`Settings`；`main()` 启动时只构造这一份快照。过渡期旧的全局变量仍然存在，由一次性的兼容写入
函数从快照回填，供尚未迁移的模块读取。

## Current State

### 问题代码定位
- `src/config.py:129-130`：`_LIBRARIES_RAW = load_libraries_from_conf()` / `LIBRARIES = _normalize_libraries(...)`。导入时就有副作用（读文件）。
- `src/config.py:133-310`：全部运行参数都是可变的模块变量；`VIDEO_EXTENSIONS`、`SKIP_CODECS`、`AUDIO_PASSTHROUGH_CODECS`、`SW_DECODE_FALLBACK_CODECS` 是可变 set，`ENCODER_PARAMS` 是嵌套 dict。
- `main.py:64-237`（`_apply_cli_overrides`）：参数解析、CLI→全局写入、`--library` 解析三件事混在一个函数里。
- `main.py:178`：`config.SKIP_CODECS.add(config.VIDEO_ENCODER)` 会原地修改模块里的 set。每调用一次都会累积，这是测试之间互相污染的直接来源。
- `main.py:234-235`：`--library` 解析结果直接写回 `config._LIBRARIES_RAW` / `config.LIBRARIES`。

### 相关现有实现（可复用）
- `src/config.py:_normalize_libraries` — 把 raw 库定义规范化为 `{name: {input, output, cache}}`，`LibraryProfile` 直接从它的输出构造。
- `src/config.py:_parse_library_value` / `load_libraries_from_conf` — `libraries.conf` 解析，复用，不重写。
- `src/config.py:ensure_libraries_conf` — 缺失时生成模板，保留原有调用点（`main.py:475`）。
- `tests/conftest.py:make_history` 等工厂 fixture — 新增的 `settings_factory` 沿用同样的“工厂 fixture”风格（ARCHITECTURE_PLAN §9 第 5 条已有约定）。

### 数据流 / 调用链
```
main() → _apply_cli_overrides() → argparse → config.X = ... (全局写入)
       → main_loop() → 读 config.* 构造 History / Scorer / TranscodePipeline
       → 业务模块运行期继续读 config.*
```
