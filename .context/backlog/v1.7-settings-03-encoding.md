## Context

转码这一侧仍有三个模块直接读全局 config：`ffmpeg_runner._build_ffmpeg_cmd` 读编码器参数、
GOP/look-ahead、音频直通、字幕/附件开关；`transcoder.transcode_stage` 读临时目录前缀、软解回退
编解码器和转码超时；`probe.VideoProbe.get_frame_count` 读帧数探测超时。测试只能靠
`patch("src.config.VIDEO_ENCODER")` 这类全局补丁来控制命令构造（`test_transcoder.py`），
所以 FFmpeg 命令的生成规则没有一个显式的输入。

## Goal

FFmpeg 命令完全由 `EncodingProfile` 和调用参数决定，转码阶段的超时和临时目录来自
`pipeline.runtime`，帧数探测超时通过 `VideoProbe` 的构造参数注入。上述三个模块不再
`import src.config`，生成的 FFmpeg 命令与迁移前逐字节一致。

## Target State

### 方案描述
1. `ffmpeg_runner._build_ffmpeg_cmd(..., probe=None, *, encoding: EncodingProfile)`：`encoding` 作为**必填**关键字参数，函数体内 `config.X` 一一替换成 `encoding.x`。删除 `from src import config`；docstring 里对 `config.SW_DECODE_FALLBACK_CODECS` 的引用改成 `EncodingProfile.sw_decode_fallback_codecs`。
2. `VideoProbe.__init__(self, ffprobe_path, frame_count_timeout=600)`：默认值等于现在的 `config.FRAME_COUNT_TIMEOUT`，这样 `test_probe.py` 里 `VideoProbe("")` 这类构造不用改。`probe.py` 删除 `from src import config`。
3. `TranscodePipeline` 构造 `VideoProbe(paths.ffprobe_path, frame_count_timeout=runtime.frame_count_timeout)`；新增只读属性 `encoding`。
4. `FfmpegVMAFScorer` 新增构造参数 `frame_count_timeout`，传给内部的 `VideoProbe`；`main.py` 构造评分器时传 `settings.runtime.frame_count_timeout`。这是本任务唯一允许的 `main.py` 改动。
5. `transcoder.transcode_stage`：`pipeline.runtime.temp_prefix`、`pipeline.encoding.sw_decode_fallback_codecs`、`pipeline.runtime.codec_timeout`；调用 `_build_ffmpeg_cmd(..., encoding=pipeline.encoding)`。删除 `from src import config`。
   - **按库策略预留**（见 `docs/ARCHITECTURE_PLAN.md` §7 候选池，非本期）：阶段函数只能通过 `pipeline.encoding` 这一个入口取 `EncodingProfile`，不要在 helper 之间层层透传零散字段。将来按库覆盖时，只需要把这个入口改成按 job 所属的库查找。
6. 测试：
   - `test_transcoder.py` 中 `_build_ffmpeg_cmd` 的用例改为传 `encoding=settings_factory(...).encoding`，删掉全局 patch。
   - 新增**命令快照测试**：用默认 `EncodingProfile` 和一个固定的 mock `probe`（视频 + 两路音频 aac/ac3 + 字幕 + 附件），在 av1 编码器下分别覆盖普通、`sw_scale_fallback`、`sw_decode_fallback` 三种情况，断言 `cmd` 列表与迁移前完全相等。**先在迁移前的代码上生成期望值并提交**，再改实现。
