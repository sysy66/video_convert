## Context

1. **关停被误记 failed（bug）**：`transcode_stage` 的 `_fail()` 不检查关停标志。收到 SIGTERM 后 `kill_active_ffmpeg()` 杀掉转码子进程，ffmpeg 非零退出走到 `_fail()`，记录被写成 `failed`。正常关机打断的任务从此不会被自动恢复，只能靠 `--retry-failed`。后处理阶段（`post_process_stage`）早已有这个守卫，转码阶段漏了。
2. **两套关停标志**：`main._running` 与 `runtime.shutdown._shutting_down` 由 `signal_handler` 同时置位，语义相同，容易只改一处。
3. **媒体库输入目录重叠**：如果一个库的 input 是另一个库 input 的祖先目录，同一个文件会被两个库扫到；启动恢复时 `_find_lib_for` 按配置顺序取第一个匹配，可能匹配到错误的库，产物落到错误的输出目录。

## Goal

关停打断的转码保持 `pending_transcode`，下次启动自动恢复；进程只有一个关停标志；输入目录重叠的配置在启动校验时报错退出。

## 复杂度说明（必填）
- **真实问题证据**：第 1 项见 `src/application/transcoder.py:_fail`（无 `is_shutting_down()` 判断），对照 `post_process.py:post_process_stage` 的同类守卫；第 2 项见 `main.py:signal_handler`；第 3 项见 `main.py:requeue_entry._find_lib_for`。
- **学习项**：否。
- **新增清单**：无新模块、无新配置项、无表结构变化；`validation.py` 新增一条校验。
- **更轻的方案**：第 3 项可以只打 warning 而不报错。不选：重叠配置会让产物落错目录，属于配置错误，应该在启动时拦住。
