## Context

VMAF 打分使用的 ffmpeg 子进程（`ffmpeg_vmaf_scorer.py`）通过 `subprocess.run()` 启动，
既未注册到 `process_guard`，也不感知 `shutdown` 标志。

收到 SIGTERM 后，`main.py` 的关停流程先调用 `pool.shutdown(wait=True)`——这会等待所有
正在运行的 Future 完成。运行 VMAF 打分的线程阻塞在 `subprocess.run()` 上，而该子进程
没有被发送任何信号，因此会一直运行到自然结束或 `VMAF_TIMEOUT`（默认 36000 秒，10 小时）
才会超时。`kill_active_ffmpeg()` 在 `pool.shutdown()` 之后才被调用，届时 VMAF 进程早已
不在注册表里，调用无效。

实际后果：发出 SIGTERM 后，守护进程最长需等待一整部影片打完分（数小时）才能退出。

属于 v1.7 稳定性条目：「VMAF 子进程可中断」。

## Goal

SIGTERM 后，守护进程在数秒内完成关停：正在运行的 VMAF ffmpeg 子进程被立即终止，
后处理状态保持 `pending_postprocess`，下次启动直接恢复打分，不重新转码。

## Target State

### 方案描述

**改动一：`src/media/ffmpeg_vmaf_scorer.py` — `_run_vmaf()` 改用 Popen**

把 `subprocess.run()` 替换为 `Popen + communicate()`，在 `communicate` 前后注册/注销 PID，
使 `kill_active_ffmpeg()` 能感知到该进程：

```python
from src.runtime.process_guard import register_ffmpeg_pid, unregister_ffmpeg_pid

# 替换原来的 subprocess.run(cmd, ...) 块：
proc = subprocess.Popen(cmd, stdout=subprocess.PIPE, stderr=subprocess.PIPE)
register_ffmpeg_pid(proc.pid)
try:
    stdout, stderr = proc.communicate(timeout=self.timeout)
    result_rc = proc.returncode
except subprocess.TimeoutExpired:
    proc.terminate()
    try:
        proc.wait(timeout=5)
    except subprocess.TimeoutExpired:
        proc.kill()
        proc.wait()
    unregister_ffmpeg_pid(proc.pid)
    log.warning("VMAF [%s] timed out for %s", tag, os.path.basename(str(dist_path)))
    return None
except Exception as e:
    unregister_ffmpeg_pid(proc.pid)
    log.warning("VMAF [%s] failed for %s: %s", tag, os.path.basename(str(dist_path)), e)
    return None
finally:
    unregister_ffmpeg_pid(proc.pid)

# 后续逻辑用 result_rc / stderr（bytes decode）替换原来的 result.returncode / result.stderr
```

注意：`subprocess.run(capture_output=True)` 把 stdout/stderr 都捕获；
改 Popen 后需同样捕获两者（`stdout=PIPE, stderr=PIPE`），`communicate()` 返回 `(stdout_bytes, stderr_bytes)`。
当前 `_run_vmaf()` 只用 returncode 判断成功，score 读自 json 文件，stderr 仅在日志中用到——
改后 stderr bytes 需 `.decode('utf-8', errors='replace')` 再传给日志即可。

**改动二：`main.py` — 调整关停序列，`kill_active_ffmpeg()` 前移**

```python
# main() 的 finally 块，原来：
#   transcode_pool.shutdown(wait=True, cancel_futures=True)
#   post_pool.shutdown(wait=True, cancel_futures=True)
#   kill_active_ffmpeg()   ← 在 main() 的 finally 里

# 改为在 main_loop() 的 finally 块中前移：
finally:
    kill_active_ffmpeg()                                    # ← 先杀，立即中断 VMAF/转码子进程
    transcode_pool.shutdown(wait=True, cancel_futures=True) # ← 线程很快退出（进程已被杀）
    post_pool.shutdown(wait=True, cancel_futures=True)      # ← 同上
```

`kill_active_ffmpeg()` 前移后，`main()` 的 finally 里的那一行可以保留作为安全兜底（幂等，
注册表已空时直接返回），也可以删除（Spoke 保留即可，无副作用）。
